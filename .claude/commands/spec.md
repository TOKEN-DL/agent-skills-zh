---
description: 开启规范驱动开发，在写代码前先写一份结构化规格说明
---

调用 agent-skills:spec-driven-development Skill。

先弄清用户想构建什么。围绕下列点问澄清性问题：

1. 目标与目标用户
2. 核心功能与验收标准
3. 技术栈偏好与约束
4. 已知边界（始终要做的事、要先问的事、绝不能做的事）

然后产出一份覆盖全部六大核心领域的结构化 spec：目标、命令、项目结构、代码风格、测试策略、边界。

若请求把若干彼此独立可测试的能力捆在一起，先按 Skill 的 Phase 0 给出一份能力地图（模块 ID、依赖方向、构建顺序）并获得批准，再按依赖顺序逐模块 spec。

把 spec 另存为项目根的 SPEC.md，并在继续前与用户确认。
