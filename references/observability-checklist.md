## 值班问题（从这里开始）

没有问题的遥测是噪声。埋任何东西之前：

- [ ] 把 2-4 个值班工程师会问这个特性的问题写下来
- [ ] 下面的每条信号能映射到这些问题之一
- [ ] 每个问题匹配对的信号类型：metrics 说**什么**出了问题，traces 说**哪里**，logs 说**为什么**

## 结构化日志

- [ ] 日志是结构化（JSON）的、稳定的事件名 ， 不是自由格式字符串
- [ ] 每一行带一个关联 / 请求 ID，在系统边界生成或接受
- [ ] 关联 ID 在每次外部调用与 async 边界（HTTP 头、队列元数据）上传递
- [ ] 任何被多条入口（调度器、重放端点、手工跑）写的日志流都带一个入口点字段，在跑开始时设上、与关联 ID 一起传下去
- [ ] 日志级别一致：`error` = 不变量被打破，可能要人处理；`warn` = 降级但已处理；`info` = 重要业务事件；`debug` = 生产默认关
- [ ] 任何日志行都不能有密钥、token、密码或未经去标识化的 PII（`security-and-hardening` 硬规则）
- [ ] 字段要白名单 ， 不记整份请求 / 响应体、不记认证头
- [ ] 外部服务调用只记元数据：端点、状态、延迟、尝试次数、去标识化的标识
- [ ] 抽查实际日志输出：结构化字段、不是 `[object Object]`

## 指标

- [ ] **RED** 给每个 endpoint 与每个外部依赖：Rate、Errors、Duration
- [ ] **USE** 给每种资源（队列、池、主机）：Utilization、Saturation、Errors
- [ ] 延迟用直方图；p50/p95/p99 可查 ， 永远不用平均值
- [ ] 所有 label 来自小且固定的集合（路由模板、状态类、供应商名）
- [ ] 不能有无界 label 值：不用 user ID、tenant ID、邮箱、原始 URL、请求 ID、错误消息文本
- [ ] 状态码按类分组（`5xx`，不是 `503`）
- [ ] 每个 worker / 队列都跟踪队列深度与处理时长

## 分布式追踪

- [ ] OpenTelemetry（或等价物）在服务启动时初始化，且先于其它 import
- [ ] 为 HTTP、gRPC、DB 客户端开启自动埋点
- [ ] 每次外部调用都传递 trace context（W3C `traceparent` / `tracestate`），每次入站请求都抽取
- [ ] Context 跨过 async 边界 ， 队列消息带 trace 元数据
- [ ] 手工 span 只加在有意义的内部工作单元上，附值班会用来过滤的属性
- [ ] span 属性里不出现密钥或 PII
- [ ] head-based 采样默认低比率；如支持 tail sampling 则保留 100% 错误

## 告警

- [ ] 每条告警都是按症状（错误率、p99、队列年龄）， 按原因（CPU、磁盘、重启）放仪表板、不叫醒
- [ ] 每条告警都可执行；"忽略它、它自愈了"那种直接删
- [ ] 每条告警链一条 runbook ， 最少三行：什么意思、先查什么、升级给谁
- [ ] 阈值与时长由 SLO 或历史数据支撑，不是凭猜
- [ ] 只用两档严重级：**叫醒**（面向用户、立刻处理）和**开 ticket**（退化、本周处理）
- [ ] 每条新告警测发过一次：落到对的频道、runbook 链接打得开
- [ ] 不会出现"每天响、确认但不行动"的告警

## 仪表板

- [ ] 有服务健康仪表板：错误率、p99、流量、饱和度
- [ ] 依赖健康面板展示每个服务的错误率与延迟
- [ ] 仪表板能回答清单顶部的"值班问题" ， 不是"看完一切、除了答案"
- [ ] 默认时间范围合理（1h-6h，不是 30d）

## 校验遥测本身

埋点也是代码；它也会错：

- [ ] 在 staging 强制出一个错 → 用关联 ID 在日志里找到它
- [ ] 发测试流量 → 指标序列出现，label 与值合理
- [ ] 在追踪 UI 里跟一个请求端到端 → 跨度没断
- [ ] 一次诱导的故障只用遥测、没读源码就定位了

## 上线前闸

特性在进生产之前，下面这一组全部为真：

- [ ] 结构化日志流到日志聚合系统
- [ ] 每个新 endpoint 与依赖的 RED 指标在仪表板可见
- [ ] 至少配了一条按症状的告警，带 runbook、且测发过
- [ ] 一个请求能跨过它碰到的每个服务被追踪
- [ ] 值班知道 runbook 在哪

上线日的监控顺序与回滚触发，见 `shipping-and-launch` Skill。
